かぐやAI 操作マニュアル

文字会話・長期記憶・定型の声かけ。Windowsの既存開発環境で使う個人用アプリです。

1. 起動と停止

  1. C:\kaguya-ai\start.batをダブルクリックします。
  2. 初回はDBの追加項目を準備し、画面と実行ファイルをビルドします。既存の会話は消しません。初回ビルドには数分かかる場合があります。追加パッケージは自動取得しません。
  3. 「かぐやAI」が開き、入力欄が有効になれば会話できます。既に起動しているときは既存の画面を表示します。
  4. 終了はタスクトレイの「終了」、キャラクターの右クリック→「終了」、またはstop.batです。ウィンドウの×は非表示にするだけです。
  5. 入力欄はEnterで送信、Shift+Enterで改行です。返事を待っている間も次の文章を書けます（送信は返事が届いてから）。

保存済みの記憶は終了後もDBに残ります。生成中・未保存の回答は終了すると失われる場合があります。「保存のみ再試行」で保存してから終了してください。PostgreSQLサービスはアプリ終了時に止めません。

必要な既存環境：PostgreSQL、backend/.venvのPythonとrequirements、Node.js/npm、Rust/MSVC、WebView2。配布用インストーラーやPythonの同梱はありません。このフォルダーを別PCへコピーしただけでは動きません。

2. 会話する

  • 「会話」で文章を入力し「送信」。最大2,000文字、同時に1件です。
  • 「生成停止」で自分の端末から送った会話の生成を止めます。外部APIの処理や利用枠消費まで停止する保証はありません。
  • 失敗した会話は「再送する」で同じIDを使って再試行します。回答が生成済みで保存だけ失敗した場合は「保存のみ再試行」を選びます。
  • 「以前の会話を読み込む」で過去の履歴を50往復ずつ表示できます。
  • 切断後は再接続して履歴を取り直します。勝手に回答を再生成しません。

3. 設定する

「設定」で変更し、「設定を保存」を押します。保存した設定は次回起動後も有効です。APIキー・DB接続情報は画面に表示しません。

設定意味・初期値
声かけ停止初期はOFF。ONでもユーザーからの会話には応答します。
記憶の自動整理初期はON。日本時間03:00、起動時に未実行分を回収します。起動後60秒は待ち、会話中は新しい整理を始めません。
声かけ間隔60〜240分、初期60分。起動挨拶も含め、この間隔より頻繁には表示しません。
整理APIの1日上限1〜3回、初期3回。手動・自動・週次・失敗した呼び出しも含みます。会話APIは別です。
回答の出力上限256〜2,048トークン、初期1,024。文字数ではありません。
最前面表示初期ON。Tauriの画面に適用します。
文字サイズ12〜22、初期14。

Geminiモデルと秘密情報は従来どおりbackend/.envで管理します。変更後は本体を終了して起動し直してください。モデルの料金や利用枠をアプリから判定する機能はなく、有料モデルへの自動切替もありません。

4. 記憶を整理する

「設定」→「今すぐ整理」で日次・週次と同じ処理を実行します。完了・失敗・本日の呼び出し回数を画面で確認できます。

  • 未処理のユーザー発言を古い順に最大30件ずつ、入力予算内で選びます。AIの回答をユーザーの好みの根拠にはしません。
  • 長く使う好みや事実を「知恵」にまとめ、次の会話では日本語の部分一致で関連する知恵を最大5件参照します。言い換えや曖昧な表現では検索に出ない場合があります。
  • 形式・根拠ID・更新番号を検証してから、知恵と処理済み状態をまとめて保存します。失敗した対象は未処理のまま残します。再実行しても同じ根拠IDを重複加算しません。
  • 週次は日曜03:00を基準に、別日3日以上の明示的根拠があり、新しい知恵があるときだけ接し方を1項目更新します。固定性格は変更しません。
  • 整理が成功すると、処理済みで7日を過ぎた元の会話を削除します。未処理は自動削除しません。知恵の要旨・根拠の短い抜粋は残ります。

会話と整理に必要な内容は、設定中のGeminiへ送信されます。整理を自動で送りたくない場合は「記憶を自動整理する」をOFFにしてください。「今すぐ整理」はOFFでも実行できます。失敗時の自動再試行はなく、手動再実行も日次上限に従います。

5. DBの記憶を確認・訂正・削除する

  1. 「記憶」を開き、「会話の原文」「知恵・好み」「接し方」を選び、「表示・更新」を押します。原文・知恵は部分一致検索ができます。
  2. 「根拠・処理情報」を開くと、根拠ID、日付、種類、処理済み時刻などを確認できます。表示は30件ずつです。
  3. 「訂正」または「削除・関連記憶も取消」で対象と影響件数を確認します。訂正する場合は文章を直して「確認して実行」を押します。

訂正・削除は取り消せません。古い情報の復活を防ぐため、関連する情報も保守的に取り消します。会話中・回答未保存の間は操作できません。

操作対象関連する変更
原文の訂正ユーザー発言を訂正し未処理へ戻します。その古いAI回答を削除し、派生した知恵・接し方・過去値を取り消します。AI回答自体の訂正はできません。
原文の削除同じ会話IDの往復と、そこから派生した知恵・接し方を対象にします。
知恵の訂正・削除根拠の元会話と共有する派生記憶も削除・取消します。訂正した知恵は自動更新から保護されます。
接し方の訂正・削除根拠の知恵・元会話、過去値も対象です。削除時は中立の接し方へ戻します。訂正時は自動更新から保護できます。
接し方を直前へ戻す自動更新前の値がある場合だけ実行できます。復元後は自動更新から保護し、過去値は消去します。

原文の期限削除は「忘れてほしい」という操作とは異なり、知恵を残します。忘れさせたい情報は「記憶」で対象の知恵を削除してください。外部送信済みデータまで削除する機能はありません。

6. 自発的な声かけ

Windows画面が表示され、PCが操作可能な状態で、起動挨拶または最後の会話から設定した間隔が経つと定型の吹き出しを出します。LLM・音声・DB会話保存は使いません。

  • 返事がなければ追加で話しかけません。最後の声かけ日時と返事待ちは再起動後も保持します。
  • 非表示・最小化・PCロック中・会話生成中は表示しません。復帰後も連続表示しません。
  • 「静かにする」、トレイの「静音／声かけ再開」、設定、または会話の「静かにしてて」で停止できます。
  • 再開はタイマーをリセットし、すぐには話しかけません。
  • 声かけに返事をすると、直前の定型文1件を会話文脈に渡します。原文や知恵の根拠には保存しません。

7. 困ったとき

表示・症状確認すること
Pythonを起動できない既存のPythonとbackend/.venvが使えるか確認します。自動で再インストールはしません。
Database setup failedPostgreSQLサービスが起動しているか、backend/.envの接続先をPC内で確認します。キー・パスワードをチャットへ貼らないでください。
ポート8765を使用できない別起動のかぐやAI・開発サーバーを、その起動元から終了します。他のアプリを強制終了する機能はありません。
Geminiの利用制限表示された待ち時間を目安に手動再送します。課金や別モデルへの切替は自動実行しません。
整理結果の検証失敗原文は残っています。上限以内で「今すぐ整理」を再実行できます。手動で保護した知恵との競合などは記憶画面で確認してください。
記憶が更新された別の処理と競合しました。再表示してから操作し直してください。
画面が見つからないタスクトレイのアイコンをクリックするか、start.batを再実行します。

設定・整理回数の保存先：%LOCALAPPDATA%\KaguyaAI\settings.json。会話本文の複製はこの設定ファイルに保存しません。DATA_DIR環境変数で保存先を変更できます。壊れた設定ファイルを黙って初期化して予算をリセットすることはありません。

コードの検証はcheck.bat。実DB・Geminiへ接続しない単体テストとフロントエンドのチェックを実行します。別途用意したDB結合テストは専用のテストDBだけに使用してください。
